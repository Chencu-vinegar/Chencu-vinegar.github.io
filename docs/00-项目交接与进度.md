## 5. 源文件关键信息（新对话注意）

- **入口**：`index.html`（单页，所有区块集中在此文件）。
- **样式**：`styles/main.css` —— 主题用 CSS 变量（`:root` 浅色，`[data-theme="dark"]` 深色）；表单通用类 `.field` 同时服务联系表单与反馈表单。
- **交互**：`scripts/main.js` —— 纯原生 JS，无依赖；数字分身调用后端 `/api/chat`（失败回退本地关键词回复），意见反馈调用 `/api/feedback`。两个表单（`.feedback-form` 与 `.contact-form`）共用同一提交流程。
- **后端**：`server.py`（Python 零依赖，仅标准库）——静态托管 + `/api/chat` 转发 DeepSeek + `/api/feedback` 写入 Supabase + `/api/health` 返回功能启用状态；所有密钥从 `.env` 读取，前端不暴露。
- **数据库**：`sql/feedback.sql` 建 `public.feedback` 表（`id/nickname/contact/category/message/page_url/user_agent/created_at`），开启 RLS 且只放行匿名 `insert`；服务端用 **anon key** 写入，读取需登录 Supabase 控制台。
- **区块顺序**：Hero → 关于我 → 经历 → **数字分身** → 联系我 → **意见反馈** → 页脚（作品区块暂未展示，已移除）。
- **HTML 锚点**：`#about` `#experience` `#avatar` `#contact` `#feedback`。

- **本地服务启动（Windows 注意）**：`Start-Process py server.py` 在本环境会留下多级僵尸进程（`py.exe` → `python3.exe` → `python.exe` 抢同一端口，`SO_REUSEADDR` 使旧进程继续截获请求），且子进程会随调用方 shell 结束被回收。可靠做法：用 WMI 脱离进程树启动，脚本见 `.deepworks/tmp/run-server.cmd`：
  ```powershell
  ([wmiclass]'Win32_Process').Create('cmd.exe /c "D:\个人主页\.deepworks\tmp\run-server.cmd"')
  ```
  排查残留进程时按进程名过滤（`-Filter "Name = 'python.exe'"`），**不要**用 `CommandLine -match 'server\.py'`，否则会匹配到当前 shell 自身并把命令打断。
