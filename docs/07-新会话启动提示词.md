# 07 新会话启动提示词

> 用途：**换到新对话时，把下面的提示词整段复制过去**，新会话就不会丢失进度。
> 原则：本文件只是「入口」，事实以仓库文件为准 —— 新会话读完 `docs/00` 与 `git log` 即可对齐。

## 使用方法

| 场景 | 发哪条 |
| --- | --- |
| **任何新对话的第一条消息** | 提示词 A（接手项目） |
| 想补个人经历 / 作品素材 | 提示词 A → 然后 B |
| 想调整视觉、版式、配色 | 提示词 A → 然后 C |
| 想看反馈 / 加通知 | 提示词 A → 然后 D |
| 想让线上数字分身接真 AI | 提示词 A → 然后 E |
| 线上打不开 / 样式错乱 / 提交失败 | 提示词 A → 然后 F |
| 不知道怎么描述需求 | 提示词 A → 直接用大白话说明想改什么 |

## 提示词 E · 让线上数字分身接真实 AI

```text
（先发提示词 A）

背景：DeepSeek 密钥必须留在服务端，所以现在 GitHub Pages 上的数字分身是「演示模式」
（main.js 里 localReply 关键词回退）。我想让线上也能真实对话。

要求：
1. 方案：用 Vercel 或 Cloudflare Workers 部署一个只做代理的 Serverless 函数
   （对应本地 server.py 里的 /api/chat）。
2. 人格与知识（SYSTEM_PROMPT）沿用 server.py 顶部的那一份，保持单一来源、不要分叉。
3. 前端把聊天接口地址做成可配置项（例如写进 scripts/config.js 的 SITE_CONFIG），
   不要硬编码，并且**请求失败必须仍然回退到演示模式**，页面绝不报错。
4. 密钥只存在 Serverless 平台的环境变量里（服务端 Secrets），前端一行都不能有；
   顺便加基础限流/长度限制，避免被刷。
5. 先在本地把完整链路验证通过，再指导我上线，并保留「随时改回演示模式」的开关。
```

## 提示词 F · 线上故障排查

```text
（先发提示词 A）

线上出问题了，现象是：____（打不开 404 / 样式丢失 / 中文乱码 / 图片不显示 /
反馈提交失败 / 数字分身报错 / 改动推送后没生效）

请按这个顺序排查并直接动手修，不要只给我建议：
1. 先跑 python .deepworks/tmp/check_deploy.py https://chencu-vinegar.github.io/
   （它会报告首页与每个静态资源的状态码和字节数）。
2. 对照常见原因：
   - 404：Pages 是否启用、构建是否失败（仓库 Actions/Pages 页签）、分支是否选对 master/(root)
   - 样式/脚本丢失：资源是否用相对路径、文件名大小写是否一致
   - 中文乱码：index.html 是否有 <meta charset="UTF-8">、文件本身编码是否为 UTF-8
   - 反馈提交失败：scripts/config.js 的地址与公钥是否与 .env 指向同一项目、CORS 预检是否放行
   - 推送没生效：是否真的 push 成功（git status / git log origin/master -1），再等 1–2 分钟或强刷缓存
3. 修完说明「根因 + 我改了什么 + 线上验证结果」。
```
