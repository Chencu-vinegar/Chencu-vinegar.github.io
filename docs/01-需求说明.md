# 01 需求说明（PRD）

> 本文档描述个人主页的**目标、受众、功能与非功能需求**，是后续结构设计、技术实现与验收的基准。文中的决策点均已标注，请在评审时逐项确认。

## 1. 项目目标

打造一个能代表「我」的线上门面，实现三个核心目标：

| 编号 | 目标 | 衡量方式 |
| --- | --- | --- |
| G1 | 让访客快速了解「我是谁」 | 首屏可在 30 秒内给出核心人设与定位 |
| G2 | 让访客了解「我做过什么」 | 作品 / 经历模块结构化、可点击、可浏览 |
| G3 | 让访客「联系到我」 | 明确的联系入口（邮箱、社媒、二维码等） |

## 2. 目标受众

> 建议至少选定 1 个「首要受众」，页面语言与侧重据此调整。

| 受众类型 | 关注点 | 侧重要求 |
| --- | --- | --- |
| 招聘者 / HR | 专业能力、经历、作品、联系方式 | 简洁、专业、信息直达 |
| 客户 / 合作方 | 服务能力、案例、作品 | 作品展示、信任背书 |
| 同行 / 关注者 | 个人观点、动态、内容输出 | 内容沉淀、博客/动态入口 |
| 好友 / 熟人 | 近况、联系方式 | 轻量、亲切 |

## 3. 核心功能（范围）

### 3.1 必备（Must-have）
- 首页 / Hero 区：姓名、一句话定位、头像、核心标签
- 关于我：个人简介、技能 / 标签、个人经历时间线
- 作品 / 项目集：卡片式作品展示，含封面、标题、简介、链接
- 联系我：邮箱、社交链接、可选的联系表单
- 响应式布局：桌面 / 平板 / 手机自适应
- 基础 SEO：标题、描述、语义化标签

### 3.2 建议（Should-have）
- 技能可视化（进度条 / 标签云）
- 简历下载（PDF 文件）
- 博客 / 动态板块（可选，静态或接入平台）
- 深色 / 浅色主题切换
- 页面导航锚点平滑滚动

### 3.3 可选（Could-have）
- 多语言（中文 / 英文切换）
- 留言 / 联系表单交互
- 访客统计（如 plausible / umami）
- 背景动效 / 粒子 / 渐变

### 3.4 不做（Won't-have，本期）
- 后台管理系统
- 会员 / 登录体系
- 在线商城 / 支付

## 4. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 首屏 LCP < 2.5s；单页资源尽量小、懒加载图片 |
| 兼容 | 现代浏览器（Chrome / Edge / Safari / Firefox），移动端为主 |
| 可访问性 | 语义化标签、对比度达标、键盘可导航、alt 文本 |
| SEO | 有意义的 title / description / 结构化数据（可选） |
| 维护性 | 内容与样式分离、组件化、易于更新内容 |
| 部署 | 静态托管即可（GitHub Pages / Vercel / Netlify / 自己的服务器） |
