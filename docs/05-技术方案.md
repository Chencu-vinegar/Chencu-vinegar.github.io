# 05 技术方案

> 描述个人主页的**技术选型、目录结构、构建与部署、性能与 SEO**。本文档已按**实际实现**更新（项目已上线 GitHub Pages）。

## 1. 技术选型（已确认并落地）

| 项 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | **纯静态 HTML / CSS / 原生 JS** | 无框架、无构建步骤、无 npm 依赖 |
| 样式 | 原生 CSS + CSS 变量 | `:root` 浅色 / `[data-theme="dark"]` 深色 |
| 主题切换 | CSS 变量 + `localStorage` | 记忆上次选择，默认浅色，无闪烁 |
| 字体 | **仅系统字体栈** | 零外部字体请求，规避商业字体授权问题 |
| 图标 / 插画 | **CSS 自绘** | 无图标库；下滚箭头、装饰块均为 CSS 绘制 |
| 脚本兼容性 | ES5 语法 | 不用 `let`/`const`/箭头函数/模板字符串，兼容面最广 |
| 后端（可选） | `server.py` | Python 标准库零依赖，仅本地开发用 |

### 1.1 数字分身（AI 对话）

- 前端 `fetch("/api/chat")` → `server.py` 转发 **DeepSeek**，密钥只存服务端 `.env`。
- **任何失败都回退**本地关键词回复（`localReply`），页面不会出现错误状态。
- ⚠️ **静态托管（GitHub Pages）没有后端** → 线上自动处于**演示模式**（状态显示「● 演示模式」）。
  若日后要让线上也接真实 AI，需要一个 Serverless 函数（Vercel / Cloudflare Workers 等）承载密钥。

### 1.2 意见反馈（双路径，自动选择）

前端的 `submitFeedback()` 按 `scripts/config.js` 是否存在来判断走哪条路：

| 模式 | 触发条件 | 路径 | 使用场景 |
| --- | --- | --- | --- |
| **A 直连 Supabase** | `config.js` 里填了 `supabaseUrl` + `supabaseKey` | 浏览器 → Supabase REST（`POST /rest/v1/feedback`） | **GitHub Pages 等静态托管**（线上实际使用） |
| **B 同源后端** | 未填 | 浏览器 → `POST /api/feedback` → Supabase | 本地 `py server.py` |

两种模式的关键约定：

- **安全**：数据库开启 RLS，策略只放行匿名 **INSERT**，不放行读取/修改/删除。
  前端用的是 Supabase **publishable / anon 公钥**（该产品本就设计为可放在浏览器里公开使用）；
  即使有人拿到它，也只能往表里写、读不到任何反馈内容。**`service_role` 密钥从未使用、绝不会出现在前端。**
- **防刷**：隐藏蜜罐字段（命中则前端假装成功、一个字节都不发出去）＋ 前后端双重长度校验。
- **校验镜像**：直连模式下前端按服务端同样的规则截断字段（`nickname` ≤50、`contact` ≤120、`category` ≤20、`page_url` ≤500、`user_agent` ≤300），避免被数据库约束打回。
- 建表 SQL：`sql/feedback.sql`（在 Supabase SQL Editor 执行一次）。

> 已实测（`.deepworks/tmp/check_deploy.py`，35 项）：CORS 预检返回 200 且允许 `content-type / apikey / authorization / prefer` 四个请求头；匿名写入已放行（用超长内容故意触发数据库约束 `23514` 验证，**不产生数据**）；`config.js` 与 `.env` 指向同一项目与同一密钥。

## 2. 目录结构（实际）

```text
个人主页/
├── index.html            # 单页主页（唯一页面）
├── styles/main.css       # 全局样式（设计 Token + 高对比色块版式）
├── scripts/
│   ├── config.js         # 公开运行配置（Supabase 地址 + publishable 公钥），须在 main.js 之前加载
│   └── main.js           # 交互：主题 / 菜单 / 平滑滚动 / 微信复制 / 反馈提交 / 分身对话
├── assets/images/        # 图片素材（avatar.jpg）
├── server.py             # 本地开发服务（静态托管 + /api/chat + /api/feedback + /api/health）
├── .env.example          # 环境变量示例（复制为 .env 填密钥）
├── sql/feedback.sql      # Supabase 建表 + RLS 策略
├── docs/                 # 项目文档（本目录）
└── README.md
```

> **不进仓库**：`.env`（密钥）、`.opencode/` 与 `opencode.jsonc`（AI 开发工具自身配置，与项目无关）、`.deepworks/`（会话临时文件）、`uploads/`（临时素材）。

## 4. 部署方案（已确认：GitHub Pages）

**采用用户名站点（User Site）**：仓库名必须是 `<GitHub 用户名>.github.io`，站点地址即为 `https://<用户名>.github.io/`（根路径，URL 最干净）。

- 仓库：`Chencu-vinegar.github.io`（Public —— 免费账号的 Pages 只支持公开仓库）
- 发布源：`master` 分支 **/(root)** 目录
- **在线地址**：https://chencu-vinegar.github.io/

部署步骤（已执行）：

1. 本地 `git push` 到 `origin master`
2. 仓库 Settings → Pages → Source 选 `Deploy from a branch` → `master` + `/ (root)` → Save
3. 等 1–2 分钟首次构建，访问站点地址验收
4. 之后每次 `git push` 会自动重新发布

**选型对比**（备查）：

| 方案 | 说明 |
| --- | --- |
| **GitHub Pages（已采用）** | 免费、与仓库绑定、适合纯静态；无需构建 |
| Vercel / Netlify | 免费额度、自动构建、可跑 Serverless 函数（日后想让线上分身接真 AI 可选） |
| Docker / 自有服务器 | 需服务器与域名，可控性最高 |

### 4.1 静态托管的功能差异（重要）

## 5. 性能与 SEO

### 5.1 性能（实测）

- 首屏资源总量：HTML 14.2 KB + CSS 19.8 KB + JS 15.9 KB（config 1.4 KB）+ 头像 17.2 KB ≈ **68 KB**。
- **零第三方请求**：无 CDN、无外部字体、无图标库、无分析脚本 —— 这是首屏速度与隐私的最大保障。
- 单页无路由、无框架运行时；`main.js` 用 `defer` 加载，不阻塞渲染。
- 图片指定宽高、头像复用同一文件（首屏与数字分身共用，仅请求一次）。

### 5.2 SEO / 基本标签

- `title`、`meta description`、`viewport`、`lang="zh-CN"`。
- 语义化标签（`header`/`main`/`section`/`footer`）、图片 `alt`。
- 可选后续：`og:` 系列标签（分享卡片）、`JSON-LD` Person 结构化数据。

### 5.3 可访问性

- 对比度达标、键盘可访问、`:focus-visible` 焦点可见、移动端可点按尺寸 ≥44px。
- 装饰性元素（页脚大字姓名、蜜罐字段）用 `aria-hidden` 对读屏器隐藏。
- 表单状态区用 `role="status"` + `aria-live="polite"` 播报。

## 6. 安全与隐私

- **密钥分层**：DeepSeek 密钥只在服务端 `.env`（`.gitignore` 已忽略）；Supabase 前端只用 publishable 公钥，配合 RLS「仅匿名 INSERT」。
- **仓库卫生**：`.env` 从未进入 Git 历史（已核查 `git log --all -- .env`）；`.gitignore` 覆盖密钥、工具配置、临时素材。
- **联系方式**：公开邮箱与微信号，手机号在页面上以「详谈时提供」呈现，避免被爬虫直接抓取。

## 7. 依赖与维护

- 生产环境**零依赖**：没有 `package.json`、没有构建产物、没有版本升级负担。
- 改内容 = 改 `index.html`；改样式 = 改 `styles/main.css` 顶部的设计 Token。
- 换 Supabase 项目：改 `scripts/config.js`（前端）+ 重跑 `sql/feedback.sql`；本地再加 `.env`。
- 回归校验：`.deepworks/tmp/check_layout.py`（版式与选择器）、`.deepworks/tmp/check_deploy.py <URL>`（部署与连通性）。
