# 05 技术方案

> 描述个人主页的**技术选型、目录结构、构建与部署、性能与 SEO**。技术选型项已标注「建议 / 可选」，请在评审时确认。

## 1. 技术选型

### 1.1 前端框架（待确认）

| 方案 | 说明 | 适合场景 |
| --- | --- | --- |
| **纯静态 HTML/CSS/JS** | 零依赖、极轻量、部署最简单 | 内容少、追求极致性能、无需构建 |
| **Astro**（建议） | 默认零 JS、内容优先、SSG、组件可选 React/Vue | 内容型单页/多页、性能好、易维护内容 |
| **Vite + Vue/React** | 组件化、生态全、SPA | 交互复杂、需要用到前端框架 |
| **Next.js** | SSR/SSG + 生态完整 | 需要 SEO 强、后续要加后端/博客 |

**默认建议：Astro 或 纯静态。最终方案（已确认）：纯静态 HTML / CSS / JS**

### 1.2 样式方案
- 建议：**纯 CSS / CSS Modules / Tailwind CSS** 之一（按框架配套）。
- 主题：用 CSS 变量实现深/浅色切换（见设计规范 Token）。

### 1.3 交互增强（可选）
- 动效：`CSS` + 可选 `GSAP` / `motion`；
- 图标：`lucide` / `heroicons`；
- 意见反馈（**已实现**）：页面表单 → 同源 `POST /api/feedback` → Supabase（PostgreSQL）`feedback` 表。
  - 密钥只存服务端 `.env`（`SUPABASE_URL` / `SUPABASE_KEY`），前端不暴露；
  - 数据库开启 RLS，仅放行**匿名插入**，密钥泄露也无法读取反馈内容；
  - 服务端做长度校验 + 蜜罐字段过滤，前端另有字数统计与状态提示；
  - 建表 SQL：`sql/feedback.sql`（在 Supabase SQL Editor 执行一次）。

## 2. 目录结构（以 Astro / 静态示例）

```text
src/
├── assets/          # 图片、图标、字体等静态资源
│   └── images/
├── components/      # 组件（Hero / About / Works / Contact / Footer）
├── layouts/         # 整体布局（Header + Footer + 内容槽）
├── styles/          # 全局样式、CSS 变量（主题、色彩、间距）
├── data/            # 内容数据（如 works.ts、experience.ts）
└── pages/           # 页面（单页 index.astro 或 各路由页）
```

> 内容建议**集中放在 `data/` 目录**，便于后期只改数据即可更新页面，实现「内容与结构分离」，方便维护。

## 5. 性能与 SEO

### 5.1 性能
- 图片懒加载 + 指定宽高避免布局抖动；首屏图片优先优化（WebP + 合适尺寸）。
- 去除未使用 CSS/JS；尽量减少第三方脚本。
- 目标：首屏 LCP < 2.5s、CLS < 0.1。

### 5.2 SEO / 基本标签
- `title`、`meta description`、`viewport`、`og:title` 等结构化标签。
- 语义化标签（`header`/`main`/`section`/`footer`）、图片 `alt`。
- 可选：`JSON-LD` Person / WebSite 结构化数据。

### 5.3 可访问性
- 对比度达标、键盘可访问、焦点可见、移动端可点按尺寸（≥44px）。

## 6. 依赖与维护
- 尽量少而稳的依赖；锁定版本。
- 内容集中在 `data/`，更新内容无需改组件。
